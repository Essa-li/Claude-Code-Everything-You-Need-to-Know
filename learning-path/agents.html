第 2 课 / 共 1 课 · 打基础 · 约 25 分钟

什么是 AI 智能体

学完这课，你能说清楚什么是 AI 智能体、它和普通 AI 应用有什么不同，判断什么时候该用（什么时候不该用）智能体，并为一个真实问题画出智能体的基本设计。

先搞懂

原课程给了一句话的定义：AI 智能体，是让大模型真正“做事”的系统：给它工具和知识，让它作用于外部世界，而不只是回答提示。

它是一个系统，由几部分配合工作。每个智能体的核心都有三样东西（原课程用旅行预订智能体举例）：

  • 环境：智能体工作的地方，比如预订平台本身。
  • 传感器：它感知环境当前状态的方式，比如查看酒店房态、航班价格。
  • 执行器：它采取行动的方式，比如预订房间、发确认信息、取消预订。

在这三样之外，还有几个关键部分：

  • 大模型：能听懂自然语言、根据上下文推理，把模糊的请求变成具体的行动计划。
  • 执行动作：没有智能体系统，大模型只会生成文字；在智能体里，它能搜索数据库、调用接口、发消息。
  • 工具访问：能用哪些工具，取决于它运行的环境和开发者给它的能力。旅行智能体可能能查航班，却不能改客户记录。
  • 记忆与知识：短期记忆是当前对话，长期记忆是客户数据库、过去的交互，比如记住你喜欢靠窗座位。

智能体有不同类型。原课程按旅行预订的例子列了七种：

类型特点旅行智能体例子
简单反射按写死的规则做，没有记忆和规划看到投诉邮件就转给客服
基于模型的反射在内部维护一个环境模型，随变化更新跟踪历史票价，标出突然涨价的航线
目标驱动有明确目标，一步步规划怎么达成订好整趟行程：航班、租车、酒店
效用驱动不只找到一个方案，而是权衡得失找最优平衡价格和便利，挑最合你偏好的行程
学习型根据反馈不断改进根据行程后的调查调整以后的推荐
分层上层智能体拆任务，交给下层智能体“取消行程”拆成取消航班、酒店、租车
多智能体系统多个独立智能体协作或竞争分别负责酒店、航班、娱乐的几个智能体

什么时候该用智能体：能用，不代表就该用。原课程说下面三种情况特别适合：

  • 开放式问题：没法提前写死每一步，需要它自己探索解决路径。
  • 多步骤流程：任务要多轮、用多种工具，不是一次查询或生成就能完成。
  • 持续改进：系统要根据用户反馈或环境信号不断变聪明。

搭智能体的三块基础：

  • 智能体开发：第一步是定义它能做什么，也就是它的工具、动作和行为。原课程用 Microsoft Foundry Agent Service 作为主要平台。
  • 智能体模式：智能体要跨多个步骤行动，没法每个提示都手写，所以要用可复用的提示和编排策略，这就是“智能体模式”。整门课都围绕最常用的模式展开。
  • 智能体框架：现成的模板、工具和基础设施，帮你接工具、观察和调试智能体、让多个智能体协作。原课程重点讲 Microsoft Agent Framework（MAF）。

跟着看

  1. 打开原课程这一课的官方中文版，先把页面顶部的介绍视频看一遍（英文，可开字幕）：

    https://github.com/microsoft/ai-agents-for-beginners/blob/main/translations/zh-CN/01-intro-to-ai-agents/README.md

    页面标题是“AI 代理及代理使用案例简介”。官方中文版把 agent 译作“代理”，本页统一叫“智能体”，是同一个意思。

  2. 在第 0 课下载好的课程文件夹里启动 Claude Code，让它用中文讲解本课的示例代码。这一步只读代码，不运行，不需要任何密钥：

    cd {{DIR}}
claude
    用中文给一个不会编程的人讲解 @01-intro-to-ai-agents/code_samples/01-python-agent-framework.ipynb ：这个旅行智能体有哪些部分？它的指令和工具分别是什么？不要运行任何代码。

    Claude 会讲到：智能体有一段“指令”（告诉它自己是谁、该怎么做），还有一个叫 get_destinations 的工具，返回一串热门旅游目的地。

  3. 对照 Claude 的讲解，在示例里认出智能体的组成部分：

    • 指令：“You are a helpful travel agent……Use the get_destinations tool……”，告诉它身份和做法。
    • 工具：@tool 标记的 get_destinations 函数，智能体需要时会自己调用。
    • 运行：agent.run("I'm looking for a warm beach destination…")，给它一个用户请求，它决定要不要用工具，再给出推荐。

    这正对应“先搞懂”里说的：大模型负责理解和推理，工具负责真正去拿信息。

  4. 再问一个问题，把示例和七种智能体类型对上号：

    这个示例里的旅行智能体，按原课程 README 里的七种类型，最接近哪一种？为什么？如果要把它升级成“目标驱动”的智能体，还需要加什么？

    答案大意：它有指令和一个工具，能按请求给推荐；要升级成目标驱动，就要让它能规划多个步骤、用更多工具（比如查航班、订酒店）去完成一整趟行程。具体措辞每次不同。

  5. 了解一下：如果想真正运行这个示例，原课程要求先准备好这些（本页的练习不需要）：

    • 一个部署了聊天模型的 Microsoft Foundry 项目；
    • 用 Azure 命令行登录（az login）；
    • 设置两个环境变量：AZURE_AI_PROJECT_ENDPOINT 和 AZURE_AI_MODEL_DEPLOYMENT_NAME。
    我想自己跑一遍示例，要花钱吗？

    原课程示例调用的是你自己 Azure 账号里部署的模型，会按 Azure 的规则计费。第 0 课会讲原课程给出的准备方法；没准备好之前，按本页的方式读懂代码就够了。

自己练一遍

  1. 任务：假设你想做一个“询盘初筛智能体”：收到客户询盘后，自动判断需求、紧迫度和适合推荐的设备。先别想技术，用这一课学的框架把它画出来。

  2. 在 Claude Code 里（或 claude.ai 上）让 Claude 陪你一起拆解。下面这段可以直接复制，方括号里换成你的实际情况：

    我是工程机械销售公司的总经理，想设计一个“询盘初筛智能体”。请按 AI 智能体的三要素帮我拆解：它的环境是什么？它用哪些“传感器”感知信息（比如询盘邮件、WhatsApp、CRM 记录）？它能用哪些“执行器”采取行动（比如生成回复草稿、在台账里登记）？哪些动作必须由人确认？我们的产品范围是 [起重设备、混凝土设备、破碎设备]。只讨论设计，不要写代码。

  3. 把讨论结果整理成一张表，记在你自己的笔记里：

    要素你的询盘初筛智能体
    环境……
    传感器……
    执行器……
    需要人确认的动作……

  4. 用“什么时候该用智能体”的三条标准判断一下：询盘初筛是开放式问题吗？是多步骤流程吗？需要根据反馈持续改进吗？如果三条都不沾，可能用一个固定的表单或规则就够了，不一定需要智能体。

检查过关

  1. 你能用自己的话说出“环境、传感器、执行器”分别是什么，并各举一个询盘场景里的例子。

  2. 你能说出简单反射、目标驱动、多智能体系统这三种类型的区别。

  3. 你的询盘初筛智能体设计表已经填好，并且标出了哪些动作必须由人确认。

容易踩的坑

能用智能体，不代表就该用。任务步骤固定、不需要探索也不需要多种工具时，普通的程序或规则往往更简单、更可靠。原课程后面的“构建可信 AI 智能体”一课会再深入讲这个问题。
